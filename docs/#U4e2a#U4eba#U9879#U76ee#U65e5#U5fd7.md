# 《进击的巨人》个人项目日志

**项目阶段：** Version 2.0 剧情重置
**更新日期：** 2026 年 9 月 9 日
**开发方式：** HTML5、CSS3、原生 JavaScript、localStorage

## 一、本阶段目标

本阶段的目标是保留已经可用的网站技术结构，彻底移除旧剧情内容，并建立可继续扩展的 Version 2.0 剧情骨架。项目继续使用原生 HTML、CSS、JavaScript 与 localStorage，不引入框架或后端。

## 二、本阶段完成内容

首先，我完成了项目的基础目录和页面结构。目前网站包括首页、剧情页、登录页、注册页、成就页、设置页、游戏介绍页、小组介绍页以及三个成员个人主页，共 11 个 HTML 页面。CSS 和 JavaScript 按功能进行了拆分，避免把所有代码集中在同一个文件中，也为后续继续开发保留了较清晰的结构。

剧情数据继续由 JavaScript 对象集中管理。当前已完成序章、第一章至第五章以及 Bad、Good、Hidden 三类结局，共 131 个短场景，并接入关键选择、调查证据、路线和结局条件。

逐字显示、点击显示全文、键盘推进与节点自动存档继续保留。新的驱动层增加了统一的选择、条件、flag、线索、路线、小游戏结果和多结局处理能力。

登录和注册系统使用 localStorage 完成。注册信息、当前登录用户以及记住的用户名都保存在浏览器本地。不同用户使用不同的存档键和成就键，访客也拥有独立的 guest 存档。该功能只用于前端课程演示，并不具备真实生产环境所需的密码加密和身份验证能力。

成就系统保留通用解锁与展示功能，目前注册三项基础成就和八项剧情成就。设置页面继续保存文字速度、音乐开关和音效开关。

## 三、视觉设计与资源调整

首页 UI 经历了多次调整。最初的页面更像普通暗色课程网站，按钮和面板感较强。后来我参考视觉小说和剧情游戏主菜单的构图，将首页改为中央大型标题与纵向菜单，并减少矩形边框和大面积实色背景。标题使用了描边、阴影和层叠效果，菜单文字增大并改为白色，以解决文字与背景对比不足的问题。

现有背景图片与角色立绘继续作为代位资源使用。后续补齐专用场景和角色素材后，只需替换剧情节点中的资源路径。

根据展示需求，首页主标题和可见中文已经调整为繁体字，动态生成的登录状态、退出登录文字和存档提示也同步转换为繁体。修改过程中保留了原有按钮 ID、页面链接和 JavaScript 事件绑定，没有改变登录、存档和剧情功能。

## 四、开发中遇到的问题

开发过程中较明显的问题是资源路径与实际文件格式不一致。早期代码按照需求预留了 JPG 路径，但后来加入的素材使用 PNG 格式，导致背景无法显示。我通过检查图片目录、尺寸和文件名，重新对应了首页、城市、城门、训练场和灾难场景的路径。

另一个问题是首页文字虽然设置了浅色，但深色描边和阴影过强，使中文菜单看起来接近黑色。后续我移除了中文字体的深色描边，强制使用纯白填充，只保留适量黑色阴影来保证文字在明亮天空和复杂城市背景上仍然清晰。

响应式布局也是需要持续检查的部分。桌面端需要保持标题和菜单的完整构图，移动端则需要避免标题过大、菜单超出屏幕或对白区域横向溢出。目前已经加入 768px 以下的媒体查询，并分别限制了标题、人物立绘、对话区域和选项的尺寸。

## 五、个人收获

通过这一阶段的开发，我对原生 JavaScript 的模块划分、DOM 事件绑定和 localStorage 数据保存有了更完整的理解。我也认识到，互动剧情项目不仅需要写出故事内容，还必须处理节点跳转、状态恢复、用户选择和界面反馈之间的关系。

在视觉设计方面，我体会到“增加元素”并不一定能提高游戏感。与其堆叠大量卡片、边框和按钮背景，不如让场景图片承担气氛表达，让文字层级负责传递信息，再使用少量暗红色作为焦点。字体描边和阴影也需要控制强度，否则虽然效果更加复杂，反而可能降低可读性。

## 六、当前不足

Version 2.0 主线已经完整可推进，但四类小游戏仍待其他开发成员实现，当前会进入安全的剧情替代流程。专用背景、人物表情、音乐和音效也尚未接入。此外，登录数据直接保存在 localStorage 中，只能作为课程功能演示。

小组名称、成员姓名、真实照片、个人介绍和具体分工仍需由各成员根据真实情况替换。后续展示前还需要继续在不同屏幕尺寸下进行测试，并检查 Chrome 和 Edge 中的字体差异。

## 七、下一阶段计划

下一阶段按现有接口实现立体机动、调查、记忆排序和 QTE 小游戏，再补齐专用场景、角色立绘与音频素材。

正式剧情和小游戏流程跑通后，再接入背景音乐、按钮音效、过场动画与扩展成就。

## 八、本阶段总结

目前项目已经拥有一条可调查、可选择、可分支并能抵达三种结局的完整主线。玩家仍可注册、登录、自动保存并解锁成就；旧版本存档会被识别并安全引导至重新开始。

## 九、Version 3.0 总部 Explore Mode

本次在不改动登录、注册、成就、设置和既有 Galgame 剧情驱动的前提下，增加了调查兵团总部俯视探索。实现分为地图数据、NPC、交互、玩家控制和探索总控五个原生 JavaScript 模块，继续使用同一个 `gameState`，只保存地图、模式、目标和剧情标记，不保存像素坐标。

总部支持 WASD、方向键与移动端长按移动，家具和地图边缘使用 AABB 碰撞。玩家可与韩吉、利威尔、驻地士兵、巨壁教祭司及公告栏交互；完成韩吉对话后目标更新为“前往玛利亚旧城区”，东侧出口随后进入第一章 Galgame 剧情。对话期间探索控制会暂停，对话结束后可恢复探索。

当前按任务范围停在总部试玩，没有制作地下街和档案室探索。正式俯视地图、玩家行走图、NPC 精灵与探索音频尚缺，所需路径和规格记录在 `剧情系统与素材接口.md`，缺少时由 CSS 占位视觉保证功能可演示。
